# Cloudflare Gateway Rules Backup & Restore Guide

## 🎯 Overview

This guide covers the complete backup and restore system for Cloudflare Gateway rules. The system consists of two main scripts that allow you to:

1. **Download/Backup** all Gateway rules in JSON format
2. **Restore** all rules exactly as they were from a backup

## 📥 Backing Up Rules

### Basic Backup
```bash
# Download all current Gateway rules
./download_all_gateway_rules.py
```

This creates:
- `gateway_rules_export_YYYYMMDD_HHMMSS.json` - Full export with metadata
- `gateway_rules_compact.json` - Clean rules-only format

### Manual Backup
```bash
# Specify custom filename
python3 download_all_gateway_rules.py > custom_backup.json
```

## 📤 Restoring Rules

### List Available Backups
```bash
./restore_gateway_rules.py --list-backups
```

### Dry Run (Preview Changes)
```bash
# Preview what would be restored (no actual changes)
./restore_gateway_rules.py --dry-run [backup_file.json]

# Preview with filter
./restore_gateway_rules.py --dry-run --filter "bootstrap" [backup_file.json]
```

### Full Restore
```bash
# Restore all rules from most recent backup
./restore_gateway_rules.py

# Restore from specific backup file
./restore_gateway_rules.py gateway_rules_backup_compact.json

# Restore specific rules only (by name filter)
./restore_gateway_rules.py --filter "DNS" gateway_rules_backup_compact.json
```

## 📋 Backup File Formats

### Full Export Format
```json
{
  "export_metadata": {
    "export_timestamp": "2025-09-06T19:23:47.123456",
    "export_source": "Cloudflare Gateway API",
    "account_id": "...",
    "total_rules": 60
  },
  "gateway_rules": [ /* array of rule objects */ ],
  "raw_api_response": { /* complete API response */ }
}
```

### Compact Format
```json
[ /* array of rule objects directly */ ]
```

## 🔧 Rule Structure

Each rule contains:
```json
{
  "id": "rule-uuid",
  "name": "Rule Name",
  "description": "Rule description",
  "precedence": 1000,
  "enabled": true,
  "action": "block|allow|isolate",
  "filters": ["dns|http|l4"],
  "traffic": "rule expression",
  "rule_settings": {
    "block_page_enabled": true,
    "block_reason": "Security reason"
  },
  "created_at": "2025-09-06T08:44:35Z",
  "updated_at": "2025-09-06T08:44:35Z"
}
```

## ⚙️ Advanced Features

### Precedence Conflict Resolution
The restore script automatically handles precedence conflicts:
- If a backup rule's precedence is already taken, it finds the next available precedence
- Reports all precedence changes during restore
- Maintains rule ordering as much as possible

### Rule Matching
Rules are matched by name for updates:
- Existing rule with same name → **UPDATE**
- No existing rule with same name → **CREATE NEW**
- Preserves all rule settings and configuration

### Filtering
```bash
# Restore only rules containing "security" in the name
./restore_gateway_rules.py --filter "security" backup.json

# Restore only DNS rules
./restore_gateway_rules.py --filter "DNS" backup.json

# Restore only bootstrap rules
./restore_gateway_rules.py --filter "bootstrap" backup.json
```

## 📊 Restore Statistics

The restore script provides comprehensive statistics:
- **Total Rules Processed**: Rules attempted
- **Rules Created**: New rules added
- **Rules Updated**: Existing rules modified  
- **Rules Failed**: Rules that couldn't be restored
- **Precedence Conflicts Resolved**: Precedence adjustments made
- **Success Rate**: Overall restore success percentage

## 🚨 Important Notes

### Before Restoring
1. **Test with dry run first**: `--dry-run` shows what would happen
2. **Backup current state**: Run download script before restoring
3. **Check precedence conflicts**: Review any precedence changes
4. **Verify account context**: Ensure correct account ID in environment

### Environment Variables Required
```bash
export CF_API_KEY="your-api-key"
export CF_API_EMAIL="your-email@domain.com"
export CF_ACCOUNT_ID="account-id"  # Optional, defaults to UCG-Fiber
```

### Read-Only Fields
These fields are automatically removed during restore:
- `id` - Generated by Cloudflare
- `created_at` - Set by system
- `updated_at` - Updated by system
- `deleted_at` - System managed
- `source_account` - System managed
- `version` - System managed

## 🔄 Common Workflows

### Complete Backup Before Changes
```bash
# Before making any rule changes
./download_all_gateway_rules.py
echo "Backup created: $(ls gateway_rules_export_* | tail -1)"
```

### Disaster Recovery
```bash
# If rules are accidentally deleted or corrupted
./restore_gateway_rules.py --dry-run  # Preview restore
./restore_gateway_rules.py            # Execute restore
```

### Selective Rule Management
```bash
# Backup and restore only security rules
./restore_gateway_rules.py --filter "security" --dry-run backup.json
./restore_gateway_rules.py --filter "security" backup.json
```

### Migration Between Accounts
```bash
# Export from source account
CF_ACCOUNT_ID="source-account" ./download_all_gateway_rules.py

# Import to destination account  
CF_ACCOUNT_ID="dest-account" ./restore_gateway_rules.py backup.json
```

## 📚 Troubleshooting

### Common Issues

**Authentication Errors**
- Verify `CF_API_KEY` and `CF_API_EMAIL` are set
- Check API key has Gateway permissions

**Precedence Conflicts**
- Use dry run to preview conflicts
- Restore script auto-resolves conflicts
- Check logs for precedence adjustments

**Restore Failures**
- Check rule syntax compatibility
- Verify traffic expressions are valid
- Review error messages in output

**File Not Found**
- Use `--list-backups` to see available files
- Check file paths and names
- Ensure backup files are in current directory

### Getting Help
```bash
./restore_gateway_rules.py --help
./download_all_gateway_rules.py --help
```

## ✅ Validation

After any restore operation:

2. **Check dashboard**: Verify in Cloudflare Zero Trust UI
3. **Monitor logs**: Watch Gateway logs for rule effectiveness
4. **Validate precedence**: Ensure rule ordering is correct
